## Что такое Admin API и Audit Logs API на OpenAI API Platform и зачем они нужны?
Admin API позволяет владельцам организации и security-командам программно администрировать организацию в API Platform: управлять инвайтами и пользователями, проектами, сервисными аккаунтами и ключами, а также назначать роли. Audit Logs API даёт неизменяемый журнал событий для аудита и безопасности (создание/изменение/удаление ключей, инвайты, изменения пользователей и проектов, попытки входа и т.п.).

Ключевые моменты:
- Admin API ключи может создавать и использовать только владелец организации.
- Удалённые через Admin API данные восстановить нельзя.
- После удаления данные удерживаются внутренне не более 30 дней.
- Потерянный Admin API ключ восстановить нельзя — нужно удалить и создать новый.
- Аудит-логирование включается в настройках организации; после включения его нельзя отключить обычным способом.

## Какие есть лучшие практики промпт-инжиниринга для OpenAI API?
Практики, которые обычно дают лучший результат:
- Использовать более новые/сильные модели, если задача сложная.
- Инструкции писать в начале, а контекст отделять явными разделителями (например, ### или тройные кавычки).
- Чётко задавать требования: цель, формат ответа, стиль, ограничения, длину.
- Показывать пример желаемого формата (шаблон ответа), чтобы модель повторяла структуру.
- Начинать с zero-shot, затем few-shot (пары примеров), и только если не хватает — думать о тонкой настройке.
- Убирать расплывчатые формулировки и заменять их точными.
- Вместо “не делай X” чаще лучше писать “делай Y” (что именно ожидается).
- Для кода помогают “наводящие” первые слова (например, `import`, `SELECT`), чтобы модель быстрее выбрала правильный паттерн.

## Знают ли модели OpenAI API о текущих событиях?
Зависит от конкретной модели: у разных моделей разные “срезы знаний” (knowledge cutoff). Если нужно отвечать с учётом свежих данных, стоит давать модели доступ к актуальной информации через инструменты: веб-поиск и/или поиск по вашим файлам/базам (File Search), чтобы она подтягивала свежий контекст во время ответа.

## Как получить BAA (Business Associate Agreement) для работы с PHI и HIPAA через OpenAI API?
Если вам нужен BAA для обработки PHI (в контексте HIPAA), нужно запросить BAA у OpenAI: написать письмо на адрес для BAA, указать компанию и сценарий использования. Запрос рассматривают индивидуально; чаще всего одобряют, но бывают исключения. Enterprise-контракт не является обязательным условием для подписания BAA. Обычно BAA покрывает большинство API-сервисов, но есть исключения.

## Что делать при ошибке “Incorrect API key provided”?
Проверь:
1) что используешь правильный ключ (и не подставляется старый ключ из переменных окружения/конфига);
2) что в проекте/скрипте не смешиваются разные ключи;
3) что при необходимости указан правильный Organization ID и настройки аутентификации.

Если после этого ошибка остаётся — обращаться в поддержку.

## Что такое OpenAI Mutual TLS (mTLS) и как это работает?
mTLS — дополнительный уровень защиты API-трафика: помимо API-ключа клиент должен предъявлять клиентский сертификат. После настройки запросы отправляются на специальный mTLS-endpoint, и доступ дадут только при наличии корректного ключа и сертификата. Настройка включает загрузку CA-сертификата, затем активацию сертификата на уровне проекта или всей организации (тогда требование “наследуется” всеми проектами). В бете поддерживается ряд основных API-эндпоинтов (чат/комплишены, эмбеддинги, аудио, файлы, батчи, responses, изображения, модерация, realtime, fine-tuning). В запросах сертификаты передаются средствами HTTP-клиента (например, в curl через `--cert`/`--key`).

## От чего зависит latency (задержка) ответов OpenAI API и как её снижать?
Сильнее всего задержку обычно определяют:
- выбранная модель;
- количество генерируемых токенов (размер ответа).

Практическая идея: выбирать модель под задачу и ограничивать длину ответа/максимум токенов, когда это возможно.

## В чём разница между prompt tokens и completion tokens?
- Prompt tokens — токены входа: всё, что ты отправил модели (инструкции, контекст, сообщения).
- Completion tokens — токены выхода: то, что модель сгенерировала в ответ.

У моделей есть лимиты на вход и на выход. Если используешь несколько вариантов генерации (например, `n` или `best_of`), суммарно может генерироваться больше “выходных” токенов.

## Где найти свой OpenAI API Key?
Секретный API-ключ находится на странице управления ключами в API Platform. Ключ нельзя публиковать и передавать другим — его нужно хранить как пароль.

## Почему я получил предупреждение по аккаунту OpenAI?
Предупреждения выдают, когда активность аккаунта вызывает вопросы по соблюдению политик и условий. Типовые причины:
- запросы/выводы, которые попадают под нарушения правил (опасный контент, харассмент и т.п.);
- попытки обходить защитные ограничения;
- злоупотребление платформой (спам/фишинг/обман), неправильное обращение с API-ключами или аномальные паттерны использования.

Предупреждение — не бан, а сигнал скорректировать использование. Если считаешь предупреждение ошибочным, обычно предлагают ответить на письмо-уведомление и приложить контекст (ID аккаунта/организации, даты, описание ситуации и шаги, которые ты сделал).

## Почему мой аккаунт OpenAI деактивировали и как подать апелляцию?
Деактивация возможна, если нарушены политики или условия использования, а также при подозрении на компрометацию аккаунта. Частые причины:
- нарушения правил по контенту и поведению;
- попытки обхода ограничений, небезопасное или запрещённое использование, неправильный шаринг аккаунта/ключей;
- повторные нарушения после предупреждений;
- подозрительная активность (в целях защиты аккаунт могут временно ограничить).

Если считаешь, что это ошибка, обычно советуют ответить на письмо о деактивации (или обратиться в чат Help Center) и предоставить идентификаторы, описание кейса и релевантные детали (включая период возможной компрометации, если он был). Чтобы снизить риск повторов — соблюдать политики, фильтровать проблемные запросы (например, модерацией) и защищать учётные данные/ключи.
